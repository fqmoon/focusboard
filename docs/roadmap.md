# roadmap

## 现在在哪

core 和 svg-render 已经落成：

- **core**：唯一的 board schema（Ajv 校验）、几何查询、lint（errors / warnings）、文字列宽（一格两列）与档位。
- **svg-render**：`toSVG(board)`，纯字符串，不碰 DOM。
- **测试**：core 覆盖校验、查询、lint、字格；svg-render 覆盖输出结构、顺序、文字、线。
- **示例**：`examples/host` 能把 `board.json` 写成 SVG 和一份静态页面；提交一次就回执一次 lint（stdout 是 JSON）。
- **自检**：`measure()` 与 `npm run check` 报每个框的列宽、折行、行溢出、汉字偏半格；`lint` 报形状与几何。

还没有：0.2.0 套索、0.3.0 样式、跨板组合。工具契约已落地：提交整块板 → 返回 `{ errors, warnings, rendered }`，传输仍由宿主决定。

## 0.1.0 —— agent 能完整调用并渲染

**目标**：agent 画出并持续维护一块板，并且知道自己画得对不对。

**状态**：core / svg-render / 工具契约（`set_board`）已实现，四条验收都有实测；剩下的只是把宿主接到真实会话上。

范围：

- **落成两个包**：core（规则库，不碰 DOM、node 里能跑）和 svg-render（渲染器，依赖 core，输出 SVG 字符串）。这是后面一切的前提。
- core 带测试。校验和几何查询是唯一可测的部分：形状校验、越界、部分重叠、悬空线、包含查询、文字容量与 `textScale` 整除。不拆就没得测，所以顺序不能反。
- **不带传输。** 没有 HTTP 端点、没有服务、没有 `boardId`、没有持久化；调用方把 `{ tier, elements }` 交给 core / svg-render，页面怎么更新也由调用方负责。
- **core 独占校验。** 板/元素/查询/lint 只有一份 schema，在 core 里；工具 schema 由它投影，不另写一套。传输、工具名、鉴权由宿主决定。

验收：

- 调用方能把 agent 给的一串元素交给 svg-render，拿到 SVG 字符串；把它放进页面就能显示，不需要手改代码。
- `lint` 结果能回传给 agent，分 errors / warnings，它在同一次调用里看到越界、部分重叠、溢出。
- `free(region)` 能问，agent 数得出还剩几格，并据此决定这一页讲多细。
- 一块板从头画到尾，全程只有 agent 在写，人只说话。

core 已经拆出；后续的工具契约与宿主不在 SDK 内。

## 0.2.0 —— 人能在板上圈选

**目标**：让人重新获得「指」的能力。

现在的约束是人只能说"那个跟缓存有关的"。套索是这条约束的补丁，不是推翻：

- 人在板上圈一块区域，套索选中其中的框和线。
- 得到圈内元素的**纯文本清单，带定位** —— "第 5 列第 2 行，标题『缓存层』"这种能直接说出口的写法。
- 清单可以一键复制，直接贴回对话，agent 就知道人说的小范围是哪几个。
- **圈选是引用，不是编辑。** 板仍然只有 agent 能改；圈选不产生任何写操作。

为什么排在 0.2：

- 它要先有一块稳定的板才有意义 —— 圈的是 agent 画出来的东西。
- 它是唯一一个"人碰板"的动作。要先确认 0.1 的通道站得住（人只说话也能推动讨论），再看这个补丁值不值得加。

## 0.3.0 —— 可自定义渲染样式

**目标**：让调用方整板替换渲染主题，元素只用语义名引用样式。

只记方向，不急细化。词表、theme 结构、是否影响折行等，等 0.1.0 和 0.2.0 稳定后再设计。
当前阶段不实现、不预留接口，也不让样式影响几何和契约。

## 待验证

- **一页多少格。** 屏幕三档当前用 18×27 / 36×24 / 48×30，绘图档用 96×60；先按这组值实现一版，实测后再调。它决定文字在手机上缩放后能否读清，也决定一块板能承载多少内容。格子越多越自由，但"选格子"会慢慢变成"摆位置"，模型又回到算几何 —— 这条要靠实际画出来才敢定。
- **箭头交叉避让。** 放弃自动布局（dagre/elk）就等于放弃自动路由。缓解只有两条：锚点分散、少画边。真要做路由就是另一个项目。
- **折叠在框线模型里的位置。** 早期分区版有折叠（溢出折成"还有 N 项"），换成纯框线后它消失了。要么生成方自己折（不画就是折），要么恢复显式折叠标记。前者简单，但人就不知道"还有东西没看"。

## 风险

最大的风险不在渲染器，在 skill。

渲染器能机械检查的部分都有 lint 兜着；剩下全是判断 —— 什么时候该开新板、先讲哪一支、讲多深算够、什么时候切回旧板、什么该擦。这些没有谓词，只能写成 skill 的约定，而约定的失效是静默的：模型没照做，不报错，只画出一张讲不清的图。

所以 skill 的边界要一直往小里压：凡是能变成 lint 的，就不要留在 skill 里。

# 用一块板讲清楚

板和话一样是讨论的载体：它只有矩形和线，没有层级、没有自动布局、没有无限画布。位置由你给，好不好看由人判断。

三个文件，都在这个目录里：

```
SKILL.md           ← 你在读的这份
focusboard.mjs     ← 单文件 CLI，零依赖，需要 node 20+
board.example.json ← 最小的板，复制它开始改
```

## 三步

```bash
cp board.example.json board.json      # 1. 写板：{ tier, elements }
node focusboard.mjs check board.json --text   # 2. 自查：每框还剩几列、有没有折行/溢出
node focusboard.mjs submit board.json --out out --page  # 3. 交付：写 out/board.svg
```

- `check` 只读，不写盘，**画之前就该跑**。
- `submit` 有 error 一个字节都不写（上一版还留着），回执里的 `warnings` 要处理掉再交付。
- 默认输出 JSON；`--text` 是人读的。看结果时你读 JSON。

## 写板的规则（工具查不出来，或只查一半）

**坐标是格子。** `x,y,w,h` 都是整数格；`x+w` 不能超页宽，`y+h` 不能超页高。

**档位是页尺寸，不是缩放。** `small 18×27`（手机）／`medium 36×24`（默认）／`large 48×30`（讲得多）／`drawing 96×60`（细节图）。换档等于重画一张，不要指望它重排已有内容。

**文字按列算，一框两列一格。** 中文 2 列、英文和数字 1 列；框的宽度预算 = `2 × w`，行数 = `h`。`check` 会直接告诉你每行占了几列、还剩几列 —— **别自己数**。

**别把框塞满。** 一行留 3–6 列余量、一框留一两行空行，人才看得下去。塞满的板没人愿意读第二遍。

**框之间至少隔 2 格。** 只隔 1 格时箭头几乎贴在两块边上；隔 0 格时两个框的边会连成一条线。

**线只连两个框的中心。** 你给 `a`、`b` 两个 id 就够，端点会自动裁到边框上。方向只由 `arrow` 决定（`b` / `a` / `both`）。

**线不带文字。** 要标注就在线旁边放一个 `border: "none"` 的 rect —— 那既是标签也是文本块。

**文字是 rect 的字段，不是独立元素。** 想写一行字就放一个无边框 rect。

**`submit` 之后一定要看一眼。** lint 只查六件事：重复 id、悬空线、越界、框与框部分重叠、线穿过某个框、文字溢出。它**不查线上谁**、不查线线交叉、不查间距丑不丑。图和你想的不一样，是常态 —— 看一眼 `out/board.svg` 再交付。

## 判断（这部分没有工具能替你）

**什么时候开新板。** 焦点变了就开新的：讲完"存哪儿"要讲"怎么读"时，不必在同一页上擦。一块板一个主题，多板由调用方并列显示。

**画多细。** 人没问的支路不要画进来。宁可一页 6 个框讲透，也不要 15 个框铺满 —— 铺满的板通常意味着你没做取舍。

**先画什么。** 先画他们已经在争的那一处，不是先画全景。板是用来收敛分歧的，不是用来展览的。

**人只说两件事**："不要哪个"、"没看懂哪处"。按这两句改，不要反问"你觉得怎么样"。他没说要的，就别加。

## 反例（这几件事别做）

- 不要为了"填满版面"增加框 —— 空着比塞满好。
- 不要在一格里写字超过容量再指望裁切 —— `check` 会报溢出，改了再交。
- 不要把长段落塞进一个框 —— 拆成几个短框，或者改用话讲。
- 不要画没有内容的框（比如只有一个"其他"）—— 想不清就先别画。

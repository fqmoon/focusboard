# 用一块板讲清楚

板和话一样是讨论的载体：它只有矩形和线，元素是平铺的一维数组 —— 没有父子、没有自动布局、没有无限画布。位置由你给，好不好看由人判断。

三个文件，都在这个目录里：

```
SKILL.md           ← 你在读的这份
focusboard.mjs     ← 单文件 CLI，零依赖，需要 node 20+
board.example.json ← 最小的板，复制它开始改
```

## 三步

```bash
cp board.example.json board.json      # 1. 写板：{ tier, elements }
node focusboard.mjs check board.json --text   # 2. 自查：每框还剩几列、有没有折行/溢出
node focusboard.mjs submit board.json --out out --page  # 3. 交付：写 out/board.svg
```

- `check` 只读，不写盘，**画之前就该跑**。
- `submit` 有 error 一个字节都不写（上一版还留着），回执里的 `warnings` 要处理掉再交付。
- 默认输出 JSON；`--text` 是人读的。看结果时你读 JSON。

## 写板的规则（工具查不出来，或只查一半）

**坐标是格子。** `x,y,w,h` 都是整数格；`x+w` 不能超页宽，`y+h` 不能超页高。

**档位是页尺寸，不是缩放。** `small 18×27`（手机）／`medium 36×24`（默认）／`large 48×30`（讲得多）／`drawing 96×60`（细节图）。换档等于重画一张，不要指望它重排已有内容。

**文字按列算，一框两列一格。** 中文 2 列、英文和数字 1 列；框的宽度预算 = `2 × w`，行数 = `h`。`check` 会告诉你每行占了几列 —— **别自己数**。

**汉字落在偶数列才齐。** 英文词、`→`、`①` 这类 1 列字符会把后面的汉字推到奇数列，`check` 报「汉字偏半格」。修法就是加减一个空格把整行推回偶数位（或把半角标点换成全角的）—— 图例行里最容易碰上。

**框里放词，不放话。** 一个有边框的框就是一个名词：缩写、术语、三五个字，最多两行。写到三行 lint 就报 `text_dense` —— 那通常不是“这个框还放得下”，而是“这里本该有几个子框”（框包框），或者该把解释挪到页尾图例。

**解释放页尾图例。** 页面底部放一条 `border: "none"` 的 rect，一行一条“术语 → 展开”：`① LWW 最后写入者胜`。框里写字时带上 `①`。图例也吃行数和列宽，写板时先给它留 2–3 行。无边框 rect 就是写句子用的，`text_dense` 不查它。

**别贴边。** 一行留 3–6 列余量、一框留一两行空行，字才不会顶在框线上。

**同级框之间至少隔 2 格。** 只隔 1 格时箭头几乎贴在两块边上；隔 0 格时两个框的边会连成一条线。这条只管平级的两个框，容器与它包住的框之间留 1–2 格就够。

**框可以包住框，但那是几何，不是父子。** 想表达「这几个属于一组」，就放一个更大的 rect 把子框圈进去：容器写在子框**前面**（数组顺序就是 z 序，后写的压在上面），边距留 1–2 格，用 `"border": "dashed"`，文字只写组名。没有 `parent` 字段，渲染器不记这层关系 —— 只要几何上严格包含，lint 就不报 `partial_overlap`；两端都在容器里的连线也不算「穿过」。包一半才是错。所以容器里要留空行，别让子框贴着容器的字。

**线只连两个框的中心。** 你给 `a`、`b` 两个 id 就够，端点会自动裁到边框上。方向只由 `arrow` 决定（`b` / `a` / `both`）。

**线不带文字。** 要标注就在线旁边放一个 `border: "none"` 的 rect —— 那既是标签也是文本块。

**文字是 rect 的字段，不是独立元素。** 想写一行字就放一个无边框 rect。

**`submit` 之后一定要看一眼。** lint 只查七件事：重复 id、悬空线、越界、框与框部分重叠、线穿过某个框、文字溢出、文字过多（`text_dense`）。它**不查线上谁**、不查线线交叉、不查间距丑不丑。图和你想的不一样，是常态 —— 看一眼 `out/board.svg` 再交付。

## 判断（这部分没有工具能替你）

**什么时候开新板。** 焦点变了就开新的：讲完"存哪儿"要讲"怎么读"时，不必在同一页上擦。一块板一个主题，多板由调用方并列显示。

**画多细。** 人没问的支路不要画进来。宁可一页 6 个框讲透，也不要 15 个框铺满 —— 铺满的板通常意味着你没做取舍。

**先画什么。** 先画他们已经在争的那一处，不是先画全景。板是用来收敛分歧的，不是用来展览的。

**人只说两件事**："不要哪个"、"没看懂哪处"。按这两句改，不要反问"你觉得怎么样"。他没说要的，就别加。

## 反例（这几件事别做）

- 不要为了"填满版面"增加框 —— 空着比塞满好。
- 不要在一格里写字超过容量再指望裁切 —— `check` 会报溢出，改了再交。
- 不要把长段落塞进有边框的框 —— 那是把结构写成了文字，拆成子框，或者写成页尾图例。
- 不要画没有内容的框（比如只有一个"其他"）—— 想不清就先别画。
